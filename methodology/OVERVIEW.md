# EADS methodology

## Mission

Make enterprise software delivery with coding agents repeatable, reviewable, traceable and safe without turning every project into a paperwork exercise.

## Core principles

1. Business intent precedes implementation.
2. Requirements describe observable outcomes, not guessed technical solutions.
3. Unknowns are recorded; agents must not silently invent business decisions.
4. Architecture decisions are explicit, reviewable and reversible where possible.
5. Every requirement has a verification path appropriate to its risk.
6. Work is delivered in small, approved increments.
7. Human approval is distinct from agent-generated validation.
8. Documentation is maintained with the code and updated when reality changes.
9. Least privilege applies to agents, tools, credentials and environments.
10. Project depth scales with complexity, criticality and uncertainty.

## Lifecycle

Discover → Define → Architect → Govern → Plan → Approve → Implement → Verify & Operate.

The lifecycle is iterative. New information can send work back to an earlier stage. A change to an approved baseline must be assessed for impact and approved at the appropriate level.

## Three project tiers

### Tier 1 — Lightweight
Small utility, isolated API or low-risk internal tool. Use a short brief, a concise technical plan, essential tests and a lightweight approval.

### Tier 2 — Standard
Departmental or enterprise application with users, data, integrations or operational ownership. Complete the core requirements, architecture, security, testing and deployment artifacts.

### Tier 3 — Critical / Enterprise
Business-critical, regulated, sensitive-data, high-scale or multi-system platform. Complete the full artifact set, formal stakeholder reviews, threat/risk assessment, data governance, operational readiness, traceability and release approvals.

The agent may recommend a tier with rationale. A human project owner approves the tier. A project can be upgraded at any time.

## What EADS is not

- It is not a replacement for an organization's SDLC, architecture review board, security policy, privacy office, change management or regulatory obligations.
- It does not prescribe microservices, a cloud provider, a programming language or a single testing framework.
- It does not make an AI agent an authorized approver.
- It does not guarantee compliance merely because a checklist is complete.
